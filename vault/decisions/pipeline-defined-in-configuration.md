# Pipeline defined in configuration

**Decision:** The pipeline is defined in one configuration file and the diagram is drawn from it; no drag-and-drop editor is built.

**Who decided:** My call, awaiting the owner's agreement.

**Why:** Changing the process means changing the file, which leaves a reviewable history. A browser editor is a large piece of work, and changing a regulated process needs its own approval and audit controls. The editor is described in the deck as a next step.

**Evidence:** No research source: our reasoning. Concepts: [[band-flow-diagram]], [[returned-case-loop]]. Same approach as [[one-configuration-file]]. Ankura's writing stresses audit ([[05-ankura-solution-sets]], search snippets, UNVERIFIED).

**Trade-off:** A team lead cannot change the process in the browser.

**What would change it:** The owner's disagreement.
